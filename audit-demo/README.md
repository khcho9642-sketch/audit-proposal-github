# AUDIT FLOW · 회계감사 워크스페이스 데모

수령자료 30개를 가정한 가상기업 한빛정밀(주)의 **PBC 분석·분류 → 조서·재무제표 연결 → 조서 매핑·부족자료 확인 → 검토대상 확인 → 조서 작성 → 회계사 검토**를 보여주는 인터랙티브 데모입니다. 재무제표도 PBC 중 하나이며, 재무상태표와 손익계산서 매핑을 각각 확인할 수 있습니다. 기존 영업 사이트와 독립된 `/audit-demo/` 경로이며 빌드·추가 설치·API 키가 필요 없습니다.

## 실행

저장소 루트에서 `python -m http.server 8765`를 실행하고 `http://localhost:8765/audit-demo/`를 여세요. `audit-demo/index.html`을 파일로 직접 열어도 실행됩니다. 파일 직접 실행 시 전체 화면·클립보드는 브라우저 정책에 따라 제한될 수 있습니다. 인터넷 연결이나 외부 폰트·라이브러리를 사용하지 않습니다.

## 화면 사용

- 상단 가로 메뉴는 **PBC 분석·분류 / 조서·재무제표 연결 / 조서 매핑 / 검토대상 / 조서 작성** 순서입니다. 스크롤 중에도 상단에 유지되며, 좁은 화면에서는 메뉴를 가로로 스크롤합니다.
- 파일을 열면 PBC 30개 목록부터 보여줍니다. 수령 PBC·분류·구조 확인의 3개 열을 유지하며 제목·설명·요약 카드·단계 막대는 PBC 화면에서 표시하지 않습니다. 파일명을 누르면 같은 행 아래에 확인 근거와 연결 조서가 펼쳐집니다.
- 상단 메뉴나 각 자료의 연결 버튼으로 이동합니다. 영상용 재생 버튼·타임라인·자동 장면 전환 단축키는 제공하지 않습니다.
- 왼쪽 사이드바와 하단 재생 바를 없애고 본문에 화면 폭을 사용합니다. 상단 오른쪽에서 전체 화면을 사용할 수 있습니다.
- 조서 매핑은 **재무제표(계정·당기·전기) → 조서 → 해당 조서의 PBC**를 같은 표에서 보여줍니다. 계정당 한 행을 유지하고 금액마다 대표 조서 하나만 표시합니다. PBC 버튼에는 해당 조서번호를 붙입니다. 조서/PBC 버튼을 누르면 그 계정 바로 아래에 하위 표준조서와 자료 목록을 펼칩니다. 6920 현금흐름표 조서는 현금흐름표 탭에서만 표시합니다. 재무제표 5종과 공통조서 탭을 제공합니다.

- 조서·재무제표 연결 화면은 각 금액 옆에 대표 조서번호·명칭을 직접 표시합니다. 현금은 4100, 매출채권은 4500, 매출은 6000, 합산된 감가상각및상각비는 6200입니다. 이는 데모 배정 규칙입니다. 표시용 소계·총계는 계산 합계로 구분합니다. Excel의 대표 조서 열도 하나로 통일하며 관련 절차는 별도 열로 남깁니다.
- 조서 작성은 **조서 리스트 / 상태 / 회계사 검토**의 3열 목록입니다. 상위 조서 24개에서 하위 표준조서를 펼치며, 작성 내용과 회계사 검토는 같은 화면 아래에서 엽니다. 검토 메모·증빙 요청 상태를 목록에도 반영합니다.
- 수령자료 30개는 PBC 분석·분류에 통합했습니다. 파일명을 누르면 구조 확인 근거·연결 조서·원본 미리보기를 함께 열며, 원본 4개는 검색·CSV 다운로드, 전체 목록은 Excel 내보내기를 지원합니다. 별도 수령자료·회계사 검토 메뉴는 없습니다.
- **6000 매출** 또는 **매출조서 Excel 열기**를 누르면 매출 표준템플릿 전체가 열립니다. 원본 7개 시트(실증절차·총괄표·분석적 검토·거래발생사실·기간귀속Test·부가세 신고서 대사·공시사항 검토)와 가상 원본 2개 시트를 제공합니다. 하위 조서를 누르면 같은 통합문서의 해당 시트가 열립니다.
- 미리보기는 실제 XLSX에서 추출한 셀·수식·서식·병합 구조를 사용하며, 행·열 번호, 셀 값·수식 표시, 시트 전환, 확대, 동일 XLSX 다운로드를 지원합니다. 고정 샘플에는 현재 검토 메모가 포함되지 않습니다. 거래별 메모와 요청 표시는 편집 화면의 **검토 메모·발견사항 Excel**로 받습니다. 샘플 열기·닫기는 거래 검토 상태를 변경하지 않습니다.
- 6010 총괄표와 6020 분석적 검토에 가상 원장 집계를 입력합니다. 6030에는 증빙 검토대상 2건, 6040에는 기간귀속 검토대상 1건을 원본 양식에 입력합니다. 6050과 6060은 필요한 자료·확인 대기를 표시합니다. 상위 매출조서의 회계사 검토 버튼에서는 검토대상 3건을 모두 선택할 수 있습니다.

## 실제 구현 범위와 시연 범위

**실제로 수행되는 작업:** 실제 가상 표의 행 수·필드·내용 유무 확인, 파일명 기간 후보 추출, 수령목록 메타데이터 기반 7영역 분류, 기존 연결 규칙을 역조회한 PBC별 조서 매핑 후보 생성, PBC 분석·매핑표 Excel 생성, 가상 요약 재무제표 5종의 계정·공시 분류, 계정별·공통 조서 분류, 수령자료 연결, 계정·조서 연결표 Excel 생성, 고정 가상 매출자료 240건 생성, 거래번호 연결, 원장 합계 계산 및 대사, 날짜·금액·증빙 연결 규칙 실행, 유형별 질의 템플릿 생성, 검토 메모·요청 표시, 현재 상태를 반영하는 유효한 `.xlsx` 생성, 원본 `.csv` 다운로드.

**미연결 범위:** 실제 AI 모델, 기존 비공개 감사 자동화 엔진, 고객자료 업로드·파서, 회사로 질의 발송, 서버 저장, 최종 감사의견. 이 화면을 기존 시스템의 실측 성능이나 실제 AI 실행 결과로 설명하지 않습니다. ‘규칙 통과’는 감사 결론을 의미하지 않습니다.

‘추가 증빙 요청으로 표시’는 현재 탭의 상태 변경입니다. 회사로 발송되지 않으며, 요청 후에도 거래는 미해결로 남습니다. 메모는 브라우저 메모리에만 있고 새로고침 시 사라집니다. 필요하면 Excel로 저장하세요.

## 고정 사례 및 검증 가능한 수치

- 수령자료 30개: 가상 원본 4개(매출원장·출고대장·시산표·재무제표)와 수령목록만 있는 26개. 추가 자료는 원본 내용 미포함·후속 검토 대기로 표시합니다. 30개 전부를 분석 완료했다고 표현하지 않습니다.
- PBC 화면에서는 30개 전체 목록의 자료 분류와 구조 확인 상태를 확인합니다. 분석 근거·파일명 기간 후보·연결 조서·Excel 내보내기는 파일명을 눌러 펼친 상세에서 접근합니다. 재무제표와 조서는 상단 메뉴에서도 열 수 있습니다.
- 30개 PBC를 계정별·공통 조서에 연결하며, 실제 조서번호와 원본 하위 조서 표제를 사용합니다. 분류는 수령목록의 업무구분을 사용하며 원문 기반 AI 분류가 아닙니다. 파일명 연도는 미검증 후보입니다. 원본 누락·빈 표·잘못된 행 구조·미매핑을 구분합니다.
- 조서별 구조 확인 자료와 원본 내용 대기 자료를 집계합니다. 6400 법인세비용에는 법인세 신고·세무조정 자료가 수령목록에 없어 추가 확보가 필요하다고 표시합니다.

- 매출원장 240건, 출고대장 239건. 매출 합계 13,273,000,000원.
- 날짜·금액·출고 연결 비교규칙 통과 237건, 검토대상 3건.
- S-0142: 2025-12-31 매출 120,000,000원, 2026-01-03 출고. 원장 143행·출고대장 142행. 인도조건·인수일을 추가 확인하며 오류로 확정하지 않습니다.
- S-0087: 매출 72,000,000원, 출고내역 미연결. 원장 88행.
- S-0206: 매출 70,000,000원, 출고금액 65,000,000원. 원장 207행·출고대장 206행.
- 원본 행 번호는 헤더 1행을 포함합니다. CSV와 다운로드된 Excel의 원본 시트에서 같은 행을 가리킵니다.
- 조서·재무제표 연결 화면은 재무제표 5종(재무상태표·손익계산서·현금흐름표·자본변동표·주석)의 가상 요약 구조입니다. B/S·P/L 세부계정 21개, 전체 표시행 51개입니다.
- 재무제표 화면은 같은 행의 **왼쪽 계정·금액 / 오른쪽 대표 조서·연결 상태·PBC 연결**로 구성합니다. PBC 버튼으로 원본 위치·연결 조서·관련 자료를 펼칩니다.
- 왼쪽은 회사명·결산일·당기와 전기 금액·구분·소계·총계를 갖춘 원 단위 비교표입니다. BS 24개 표시행, PL 13개 표시행으로 구성하며 원본 51행에 표시용 소계·총계를 중복 추가하지 않습니다. PL 비용은 양수로 표시하고 이익 계산에는 차감 부호를 적용합니다.
- 현금및현금성자산은 당기 1,832,000,000원 / 전기 1,530,000,000원, 매출채권은 2,460,000,000원 / 2,300,000,000원입니다. 자산총계는 10,322,000,000원 / 9,000,000,000원이며 각각 부채·자본 합계와 일치합니다. 매출액은 13,273,000,000원 / 11,840,000,000원, 당기순이익은 1,512,000,000원 / 1,260,000,000원입니다.
- Excel 다운로드에도 동일한 BS·PL 당기·전기 비교시트와 소계·총계가 포함됩니다. 기존 원본 51행의 행 번호는 유지합니다.
- 전기 숫자는 별도로 정한 가상 비교 가정값입니다. 수령목록의 전기 재무제표 파일에서 읽은 결과가 아닙니다. 당기 현금흐름표의 기초현금·운전자본 증감 및 자본변동표 기초잔액과 연결되도록 구성했습니다.
- 조서·재무제표 연결 화면은 계산된 매핑 결과와 PBC 연결을 즉시 표시합니다. 영상용 단계별 재생은 화면에서 제공하지 않습니다.
- 연결 완료는 대표 조서 지정 완료입니다. 조서 관련 PBC는 대표 조서에 연결된 파일이며 원본 재무제표는 별도 표시해 개수에서 제외합니다. 원본 포함/목록만을 구분하고, 관련 자료 수를 해당 계정의 증빙 확보나 내용 검토 완료로 해석하지 않습니다. 행별 자료 수는 같은 파일이 중복 연결될 수 있어 합산하지 않습니다.
- 재무상태표는 13개 세부계정, 손익계산서는 8개 세부계정과 당기순이익 요약행 1개입니다. 원본 계정명·매핑 계정·금액·원본 행·조서를 함께 표시합니다.
- `fs-mapping.js`가 재무제표 종류·계정명·구분의 정확한 일치로 구조를 연결합니다. 표 종류가 불명확한 중복 계정은 임의로 배정하지 않으며, 미매핑·중복 후보로 남깁니다. 금액과 원본 위치를 그대로 보존하고 요약행을 중복 합산하지 않습니다.
- 조서·재무제표 연결은 기존 가상 요약표를 대상으로 합니다. 실제 고객파일의 계정명 정규화·파싱이나 원문 AI 매핑은 포함하지 않습니다.
- 2025 원본 조서번호로 계정별 조서·현금흐름표·공시 및 공통 조서를 분류합니다. 6000 매출의 하위 6040 매출 기간귀속 Test에 기간귀속 검토대상 1건을 작성하고, 증빙 미연결·금액 차이 2건은 6030 매출 거래 발생사실 검토 대상으로 구분합니다. 6010·6020은 원장 집계를 입력한 샘플이며 6050·6060은 자료 확인 대기입니다. 매출 외 조서는 서식 연결·작성 대기 상태입니다.
- 재무제표 계정·금액 행마다 대표 조서 하나를 지정합니다. 한 조서는 여러 계정에 연결될 수 있습니다. 다른 관련 절차 조서는 조서 목록·PBC 연결에 보존하고 금액 연결에서는 제외합니다. 공통 조서는 감사계획·중요성·위험평가·완료 단계로 별도 관리합니다.
- 계정과 조서의 연결은 절차 확정의 시작점입니다. 실제 감사에서는 위험·주장·중요성 및 회사 특성 검토로 조서 구성과 세부 절차를 확정해야 합니다.
- app의 재무제표 CSV/Excel은 위 분류행으로 구성됩니다. 원본 행 번호 및 고유 계정 ID를 계정·조서 연결표에 함께 내보냅니다. 주석 항목 금액은 빈칸입니다.
- 매출 시연용 시산표는 매출 계정만 포함합니다. 원장↔시산표↔재무제표 대사는 매출액에서만 실행합니다. 전체 계정의 실질감사 또는 대사 완료로 표현하지 않습니다.

## 2025 원본 조서 구조

## 파일

- `statement-presentation.js`: 당기·전기 비교표와 소계·총계 계산. 기존 원본 및 매핑 ID를 보존하며 전기 가정값은 별도 관리합니다.
- `fs-mapping.js`: 재무제표 원본 행→표 종류·계정·조서의 구조 매핑과 미매핑·중복 후보 구분(UMD/CommonJS).
- `pbc.js`: 가상 PBC 구조 분석, 수령목록 분류 후보, 자료→조서 매핑 및 원본 누락 확인(UMD/CommonJS).
- `planning.js`: 가상 재무제표 5종, 계정·조서·수령자료 연결, 재무표 간 수치 정합성.
- `engine.js`: 가상자료, 비교 규칙, 조서 데이터 생성(UMD/CommonJS).
- `sample-workpaper.js`: 6000 매출 샘플 XLSX 바이트와 해당 파일에서 추출한 미리보기 셀·수식·서식·시트별 이동 위치. 오프라인 단일 HTML에도 포함됩니다.
- `xlsx.js`: 외부 의존성 없는 OOXML/ZIP 작성 및 브라우저 다운로드(UMD/CommonJS).
- `app.js`: 화면, 원본 추적, 검토 상태, CSV/Excel 내보내기. 이전 재생 함수는 제어 DOM이 없으면 실행하지 않습니다.
- `index.html`, `styles.css`: 발표·데스크톱·모바일 화면. `noindex` 적용.
- `scripts/build-audit-sample.mjs`: 사용자가 제공한 6000 매출 원본 표준템플릿에 가상 원장과 검토대상을 입력하는 Artifact Tool 빌더. 원본 템플릿 파일과 Artifact Tool이 있는 환경에서 재생성합니다.
- `scripts/read-audit-workbook-preview.py`: XLSX를 수정하지 않고 실제 셀·수식 캐시·서식·병합·열 너비·행 높이를 미리보기 모델로 읽습니다.
- `scripts/package-audit-demo.cjs`: 동일 화면 템플릿으로 초기 PBC 목록 HTML을 채우고 외부 의존성 없는 단일 HTML을 만듭니다. 저장소 루트에서 `node scripts/package-audit-demo.cjs /원하는/경로/audit-flow-demo.html`을 실행합니다.
