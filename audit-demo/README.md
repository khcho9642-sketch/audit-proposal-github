# AUDIT FLOW · 한공회 발표용 감사 자동화 데모

수령자료 30개를 가정한 가상기업 한빛정밀(주)의 매출자료를 이용해 **전체 재무제표 → 계정과목 분류 → 조서 분류 → 수령자료 연결 → 조서 작성·검토**를 연결하는 인터랙티브 데모입니다. 기존 영업 사이트와 독립된 `/audit-demo/` 경로이며 빌드·추가 설치·API 키가 필요 없습니다.

## 실행

저장소 루트에서 `python -m http.server 8765`를 실행하고 `http://localhost:8765/audit-demo/`를 여세요. `audit-demo/index.html`을 파일로 직접 열어도 실행됩니다. 파일 직접 실행 시 전체 화면·클립보드는 브라우저 정책에 따라 제한될 수 있습니다. 인터넷 연결이나 외부 폰트·라이브러리를 사용하지 않습니다.

## 발표

- 상단 **60초 시연**을 누르면 8개 장면이 순서대로 재생됩니다.
- 하단 장면 이름을 눌러 바로 이동할 수 있습니다. 좌우 방향키는 장면 이동, 스페이스는 재생·일시정지입니다(입력창·버튼에 포커스가 있으면 기본 동작 유지).
- 1920×1080 화면과 전체 화면을 권장합니다. 기본 무음이며 각 장면 자막이 표시됩니다.
- 탭을 벗어나면 자동으로 일시정지합니다. 재시작 시 자동 시연이 넣은 메모·요청 표시만 되돌리며 사용자의 별도 메모·요청 표시는 유지합니다.
- 이 산출물은 재생 가능한 웹 데모입니다. MP4 또는 실제 자동화 프로그램의 화면녹화 파일은 포함하지 않습니다.

| 시간 | 장면 |
|---|---|
| 0–5초 | 전체 재무제표 구조와 재무상태표 계정 |
| 5–11초 | 손익계산서 계정·감사영역·연결 조서 |
| 11–18초 | 계정별 조서와 공통 조서 분류 |
| 18–26초 | 수령자료 30개 연결 |
| 26–34초 | 매출 조서의 원본 거래·검토대상 상세 |
| 34–45초 | 매출 조서 초안 |
| 45–54초 | 회계사 검토·추가 증빙 요청 상태 |
| 54–60초 | 재무제표·계정·조서 연결 현황 |

## 실제 구현 범위와 시연 범위

**실제로 수행되는 작업:** 가상 요약 재무제표 5종의 계정·공시 분류, 계정별·공통 조서 분류, 수령자료 연결, 계정·조서 연결표 Excel 생성, 고정 가상 매출자료 240건 생성, 거래번호 연결, 원장 합계 계산 및 대사, 날짜·금액·증빙 연결 규칙 실행, 유형별 질의 템플릿 생성, 검토 메모·요청 표시, 현재 상태를 반영하는 유효한 `.xlsx` 생성, 원본 `.csv` 다운로드.

**미연결 범위:** 실제 AI 모델, 기존 비공개 감사 자동화 엔진, 고객자료 업로드·파서, 회사로 질의 발송, 서버 저장, 최종 감사의견. 이 화면을 기존 시스템의 실측 성능이나 실제 AI 실행 결과로 설명하지 않습니다. ‘규칙 통과’는 감사 결론을 의미하지 않습니다.

‘추가 증빙 요청으로 표시’는 현재 탭의 상태 변경입니다. 회사로 발송되지 않으며, 요청 후에도 거래는 미해결로 남습니다. 메모는 브라우저 메모리에만 있고 새로고침 시 사라집니다. 필요하면 Excel로 저장하세요.

## 고정 사례 및 검증 가능한 수치

- 수령자료 30개: 가상 원본 4개(매출원장·출고대장·시산표·재무제표)와 수령목록만 있는 26개. 추가 자료는 원본 내용 미포함·후속 검토 대기로 표시합니다. 30개 전부를 분석 완료했다고 표현하지 않습니다.
- 재무기초·매출채권·자금·재고자산·매입부채·인사·기타로 필터링하고, Excel 다운로드에 30개 수령목록을 포함합니다.

- 매출원장 240건, 출고대장 239건. 매출 합계 13,273,000,000원.
- 날짜·금액·출고 연결 비교규칙 통과 237건, 검토대상 3건.
- S-0142: 2025-12-31 매출 120,000,000원, 2026-01-03 출고. 원장 143행·출고대장 142행. 인도조건·인수일을 추가 확인하며 오류로 확정하지 않습니다.
- S-0087: 매출 72,000,000원, 출고내역 미연결. 원장 88행.
- S-0206: 매출 70,000,000원, 출고금액 65,000,000원. 원장 207행·출고대장 206행.
- 원본 행 번호는 헤더 1행을 포함합니다. CSV와 다운로드된 Excel의 원본 시트에서 같은 행을 가리킵니다.
- 첫 화면은 재무제표 5종(재무상태표·손익계산서·현금흐름표·자본변동표·주석)의 가상 요약 구조입니다. B/S·P/L 세부계정 21개, 전체 표시행 51개입니다.
- 계정별 조서 13종과 공통 조서 4종을 분류합니다. REV-01만 매출 상세 초안 시연이며, 나머지는 분류·계획 상태입니다. 조서 코드는 이 데모 자체 코드이고 특정 법인 또는 한공회 표준번호가 아닙니다.
- 한 계정에 여러 조서, 한 조서에 여러 계정이 연결될 수 있습니다. 공통 조서는 감사계획·중요성·위험평가·완료 단계로 별도 관리합니다.
- 계정과 조서의 연결은 절차 확정의 시작점입니다. 실제 감사에서는 위험·주장·중요성 및 회사 특성 검토로 조서 구성과 세부 절차를 확정해야 합니다.
- app의 재무제표 CSV/Excel은 위 분류행으로 구성됩니다. 원본 행 번호 및 고유 계정 ID를 계정·조서 연결표에 함께 내보냅니다. 주석 항목 금액은 빈칸입니다.
- 매출 시연용 시산표는 매출 계정만 포함합니다. 원장↔시산표↔재무제표 대사는 매출액에서만 실행합니다. 전체 계정의 실질감사 또는 대사 완료로 표현하지 않습니다.

## 파일

- `planning.js`: 가상 재무제표 5종, 계정·조서·수령자료 연결, 재무표 간 수치 정합성.
- `engine.js`: 가상자료, 비교 규칙, 조서 데이터 생성(UMD/CommonJS).
- `xlsx.js`: 외부 의존성 없는 OOXML/ZIP 작성 및 브라우저 다운로드(UMD/CommonJS).
- `app.js`: 화면, 원본 추적, 검토 상태, 60초 재생, CSV/Excel 내보내기.
- `index.html`, `styles.css`: 발표·데스크톱·모바일 화면. `noindex` 적용.

## 검증

```sh
node --test tests/audit-demo-*.test.js
```

데이터 기반 탐지, 대사 재계산, 원본 위치, 재무제표 간 수치 연결 및 조서 배정, 미해결 유지와 XLSX 구조·CRC·한글·서식·문자열 처리를 검증합니다. Excel은 숫자 셀과 문자열 셀을 구분하며 메모를 수식으로 실행하지 않습니다. 브라우저에서 시연, 원본 검색, 거래 전환, 메모, 다운로드도 확인합니다.
